## Confirmed Enhanced / UE5 changes relevant to this repo

- Default SteamCMD branch/app `443030` now returns the Enhanced / UE5 server build. UE4 is now the `Conan-Exiles-Legacy` / `conan-exiles-legacy` branch.
- The dedicated server install name changed publicly to “Conan Exiles Enhanced Dedicated Server”, but the `ConanSandbox/Saved/...` paths remain.
- Default save DB is now `game_0.db`, not `game.db`. On first run UE5 can copy/convert old `game.db` if `game_0.db` does not exist.
- Engine is UE5.6.1 on the tested build:
  - `LogInit: Build: ++exiles+release-CL-365199`
  - `LogInit: Engine Version: 5.6.1-365199+++exiles+release`
  - `LogNetVersion: Set ProjectVersion to 1.2.1`
  - Steam appmanifest buildid: `23654116`
- Server startup command from this repo:
  - `-log -Port=7777 -QueryPort=27015 -MaxPlayers=10`
- Enhanced merges Exiled Lands and Isle of Siptah into one server/world. Runtime logs load the Siptah mod controller/service actor even on the default map.
- RAM use is much higher under Enhanced. On the 8 GiB test CT, runtime memory quickly reached ~6.2 GiB in prior run and ~2.9 GiB early in a later restart; low-memory systems are risky.

## Important official config/migration notes

- Inflexion troubleshooting: remove stale UE4 lines from `Engine.ini` if clients cannot connect:
  - `bUseBuildIdOverride`
  - `BuildIdOverride`
- Inflexion troubleshooting: if using `-MULTIHOME=<ip>`, also use `-MULTIHOMEHTTP=<ip>` so HTTP registration uses the same IP.
- Inflexion troubleshooting: do not rename mod pak files; renamed pak files can fail to load.
- Inflexion Server INI Settings is now the best canonical reference for Enhanced settings.

## Runtime observations from the test server

Test server: `192.168.30.129`, repo path `/home/mrn/conan-exiles-server`.

### Files present after Enhanced startup

- `ConanSandbox/Saved/Config/WindowsServer/Engine.ini`
- `ConanSandbox/Saved/Config/WindowsServer/Input.ini`
- `ConanSandbox/Saved/Config/WindowsServer/ServerSettings.ini`
- `Game.ini` was not generated by default; it was created manually during RCON testing.
- `GameUserSettings.ini` was not generated.

### ServerName section

After runtime rewrite, `Engine.ini` contains:

```ini
[OnlineSubsystem]
ServerName=Seren Conan Enhanced INI Test

[OnlineSubsystemSteam]
ServerPassword=
```

This supports changing `SERVER_NAME` to write `[OnlineSubsystem]`, not relying on `[OnlineSubsystemSteam]` alone. `[OnlineSubsystemSteam]` is deprecated in current Funcom port docs for server-query usage.

### Settings that persisted when non-default

Earlier comparison marked these as “game removed” because values were default. When set to non-default and restarted, Enhanced persisted them in `ServerSettings.ini`:

- `HarvestAmountMultiplier=1.5`
- `ResourceRespawnSpeedMultiplier=0.75`
- `DurabilityMultiplier=0.5`
- `ShieldDurabilityMultiplier=0.6`
- `ChatHasGlobal=False`
- `ChatMaxMessageLength=333`
- `DayCycleSpeedScale=1.20000005`
- `UseClientCatchUpTime=False`
- `PlayerHealthMultiplier=1.25`
- `PlayerStaminaMultiplier=1.35000002`
- `ItemSpoilRateScale=0.5`

Conclusion: do not remove those settings. They are valid/current, even if defaults disappear from the runtime file.

### ClanMaxSize casing

Setting `CLAN_MAX_SIZE=7` persisted as:

```ini
clanMaxSize=7
```

Current repo writes `ClanMaxSize=...`; this should be changed to `clanMaxSize=...`.

### RCON location

Test 1: `RconEnabled=True` in the repo-generated `ServerSettings.ini` `[RCON]` section persisted in the file, but log still showed:

```text
LogRcon: Display: Rcon disabled.
```

Test 2: manually created `Game.ini`:

```ini
[/Script/Engine.GameSession]
MaxPlayers=10

[RconPlugin]
RconEnabled=True
RconPassword=<redacted-test-password>
RconPort=25575
RconMaxKarma=60
```

After restart, logs showed:

```text
LogRcon: Display: Rcon listen socket starting up using listen port 25575 ...
LogRcon: Display: Rcon is ready for client connections on 0.0.0.0:25575!
```

Conclusion: RCON should be generated into `Game.ini` `[RconPlugin]` for Enhanced; keeping only `[RCON]` in `ServerSettings.ini` is ineffective.

Inflexion settings page confirms these runtime keys are legitimate Enhanced settings, not just cache:
