Quick Start

🐧 Native Linux — Recommended for New Servers

Starting a new server? Use Native Linux. It runs upstream Linux without Wine using isolated Native volumes.

🍷 Wine — Existing Deployments

Backward-compatible path for existing Wine servers. The :latest channel remains Wine to prevent automatic cutovers.

Updating an existing docker-compose.yml deployment never switches it to Native. New installations should use docker-compose.native.yml.
🐧 Native Linux — Recommended New-Server Quick Start
Fresh Native deployment. Do not point Native at Wine volumes. Existing servers must verify a backup and run the migration plan while Wine is still running; apply owns the stop and creates new Native volumes while keeping the original Wine volumes unchanged.
mkdir conan-native && cd conan-native
curl -O https://raw.githubusercontent.com/balnaimi/conan-exiles-server/main/docker-compose.native.yml
curl -o .env https://raw.githubusercontent.com/balnaimi/conan-exiles-server/main/.env.minimal
nano .env
docker compose -f docker-compose.native.yml up -d
Native images: rolling :native or versioned :2.9.0-native. RCON is internal-only by default. Fresh named volumes are initialized for the non-root UID/GID 1000:1000; custom bind mounts must be writable by that identity. Check docker compose -f docker-compose.native.yml ps for A2S health; use the bundled rcon.py listplayers client explicitly when you need an RCON diagnostic.
Native SteamCMD updates game binaries in place. A failed update stops startup but is not transactionally rolled back; retry after correcting disk/network issues, optionally with NATIVE_VALIDATE_SERVER=true.
🍷 Update an Existing Wine Deployment
Run from an existing Wine project directory. This preserves the Wine runtime and its current volumes.
cd /path/to/existing-wine-server
docker compose pull
docker compose up -d
:latest stays Wine for backward compatibility. These commands do not migrate the deployment to Native.
🍷 Edit an Existing Wine Deployment
Back up and edit the current Wine deployment's configuration without replacing its Compose file or volumes.
cd /path/to/existing-wine-server
cp .env .env.backup
nano .env
docker compose up -d
Use Config Generator for a New Native Server
Use the visual config generator (⚙️ Config Generator tab), save the generated output as .env beside docker-compose.native.yml, then start Native.
mkdir conan-native && cd conan-native

# Save the generated config as .env in this folder

Connecting to Your Server

How to connect:
Use Direct Connect in Conan Exiles Enhanced → Enter your server IP and port 7777 (IP only, no hostname)
⚠️ Important: Conan Exiles Enhanced does not support hostnames — you must use an IP address.
CG-NAT / Tunnels: If your server is behind CG-NAT, a tunnel, a VPS port forward, or a host with multiple network interfaces, set MULTIHOME to the public or forwarded IP address that players should use. The container will also use that value for MULTIHOMEHTTP so server-browser registration comes from the same IP. Leave both empty for normal hosting.
⏱️ First Run and Updates: SteamCMD downloads and verifies the Enhanced server, while major game updates may download several gigabytes and require temporary disk space. Startup time depends on storage, memory, CPU, and cache state—verify the readiness markers instead of relying on container uptime alone.

💻 System Requirements

Enhanced / UE5 guidance: Conan Exiles Enhanced requires substantially more memory and storage than the previous UE4 dedicated server. Older Conan Exiles hardware recommendations are not reliable sizing guidance for the current Enhanced server running through Wine.
Server Profile CPU RAM Disk
Test / very small 4 fast x86-64 cores 12 GB practical start 20 GB practical start
Small private server (up to 10 players) 4+ fast x86-64 cores 16 GB recommended 25–35 GB recommended
Growing or modded server 6+ fast x86-64 cores 24 GB or more 70 GB comfortable; 100 GB heavy

These are project planning recommendations, not official Funcom requirements or hard limits. Actual usage depends on the runtime, map, database, buildings, players, mods, backups, and game updates.

Measured RAM guidance: RAM sizing uses total host/VPS allocation. 12 GB is a practical starting allocation for a small vanilla server. In measured no-player tests under a hard 10 GiB container cap with no extra swap budget, Wine peaked at 9.19 GiB and Native peaked at 8.69 GiB; both remained A2S-ready through 20-minute observation windows without cgroup pressure or OOM events, and Native completed multiple save cycles. 16 GB is recommended for typical use, not a hard minimum. The test host remained at 16 GiB, so the 10 GiB cap tested the game budget under pressure but did not reproduce whole-system pressure on a 12 GB VPS. The measured worlds were small and unmodded; players, larger worlds, and mods can require more memory.

CPU Compatibility

Epic documents SSE4.2 as the general UE5 x64 minimum CPU specification. An individual game build may choose a higher minimum. AVX and AVX2 are important Conan Exiles Enhanced compatibility diagnostics, but Funcom has not officially confirmed AVX2 as a hard requirement. 
for flag in sse4_2 avx avx2; do
  grep -qw "$flag" /proc/cpuinfo \
    && echo "$flag=yes" \
    || echo "$flag=no"
done
lscpu
VPS / QEMU: The flags visible inside the guest are what the server can use. Select a current virtual CPU model or host-passthrough when available. A host change that exposes several flags can confirm a CPU compatibility problem, but it does not isolate AVX2 alone.

Verified Runtime Observation

A clean, unmodded server using Steam build 24383534 and Wine Staging 11.10 repeatedly entered an OOM restart loop on an 8 GB host. With 16 GB, the same server reached InProgress, responded to Source/A2S queries on UDP 27015, and stabilized at approximately 9.1 GB idle memory.
🐧 Native Linux observation: On the same 16 GiB test CT and Steam build 24383534, the native Shipping binary reached A2S/RCON readiness and stabilized near 8.70 GiB unmodded. Enhanced-tagged StayBloody and Better Thralls mounted in order at roughly 8.42–8.57 GiB. The guest exposed SSE4.2, AVX, and AVX2. UE5's general x64 baseline is SSE4.2; these tests do not prove AVX2 alone is a Conan requirement.
8 GB RAM should be considered insufficient for the current Enhanced server. The measured 12 GB practical-start profile is intended for small vanilla workloads with limited headroom; choose 16 GB or more as the workload grows.
Storage guidance:
  • Storage sizing assumes one runtime—Wine or Native, not both. 20 GB is a practical starting allocation for one runtime.
  • 25–35 GB is recommended for updates, world growth, and a simple backup. 35–40 GB is a comfortable allocation, not a minimum.
  • The measured clean Wine-to-Native coexistence used about 14 GB on the host; 25 GB is a practical migration floor for that scenario, while 35 GB is recommended for safer migration headroom.
  • 70 GB is comfortable, not required, for mods, multiple backups, long-term growth, or repeated maintenance. 100 GB is a safer recommendation for heavily modded servers or long backup retention.
  • Table values are total disk allocations in decimal GB; Native preflight reports currently free binary GiB after existing host and Docker usage.
Network:
  • Stable internet with at least 10 Mbps upload recommended
  • Lower upload speeds may cause rubber-banding and lag
  • Each connected player uses roughly 30-60 KB/s of bandwidth
Good to know:
  • Wine adds CPU and memory overhead compared with native Windows
  • Game logic benefits heavily from fast single-core performance
  • RAM usage grows as players build and explore — monitor with docker stats
  • Mods may substantially increase startup time, memory use, and storage
  • No physical GPU required — the dedicated server is headless

Mods

What you do:
Add the Steam Workshop mod IDs you want to SERVER_MOD_LIST in your .env file or in the Config Generator. Use commas between IDs and keep them in the required load order.

Finding Workshop IDs

Open the Conan Exiles Steam Workshop. A mod page URL normally ends with ?id=1234567890; copy only that numeric ID.

https://steamcommunity.com/sharedfiles/filedetails/?id=3719513784
# Workshop ID: 3719513784

Setting the Load Order

SERVER_MOD_LIST=3719513784,3720904511,3361295718
Load order matters: Keep dependencies before the mods that depend on them, and follow each mod author's instructions. Changing the order can affect an existing world.
What the container does automatically:
On startup, it validates and stages the complete ordered set, downloads each Workshop item, and atomically replaces ConanSandbox/Mods/modlist.txt only after every item succeeds. Native strictly requires one non-empty usable top-level .pak per item and rejects malformed lists, duplicate package names, and ambiguous multi-PAK items. The Wine compatibility path for existing deployments preserves v2.6 legacy behavior for comma gaps, deterministic multi-PAK selection, duplicate names, and zero-byte PAKs with warnings. A bad ID or failed download preserves the last-known-good list and world.

Apply, Update, or Remove Mods

# After changing SERVER_MOD_LIST
docker compose down
docker compose up -d
docker compose logs -f
  • To update mods, restart the container; configured Workshop items are checked during startup.
  • To remove a mod, delete its ID from SERVER_MOD_LIST, restart, and verify the generated modlist.txt.
  • Back up your world before removing gameplay/content mods from an existing server.
  • After an Enhanced game update, confirm that every mod supports the current build before opening the server to players.
If startup stops: Check docker compose logs. An invalid ID, missing Workshop download, ambiguous/missing .pak, or incompatible mod stops startup while preserving the previous active list.
Verified Native Enhanced test: StayBloody (3722881816) and Better Thralls (3720904511) mounted in configured order. Conan extracted each top-level Workshop package's embedded -LinuxServer.pak, .utoc, and .ucas payload automatically.
Leave SERVER_MOD_LIST empty to run an unmodded server.

    🐧 Native Basic Commands

    docker compose -f docker-compose.native.yml up -d      # Start Native

docker compose -f docker-compose.native.yml restart    # Restart Native
docker compose -f docker-compose.native.yml logs -f    # View Native logs
docker compose -f docker-compose.native.yml logs --tail 50

    🔄 Updating Native

    SteamCMD checks Native game files at startup. Update the recommended Native container image with:

    docker compose -f docker-compose.native.yml pull
docker compose -f docker-compose.native.yml down
docker compose -f docker-compose.native.yml up -d
    Native game data and saves use separate Native Docker volumes and remain preserved during normal image updates.

    🍷 Existing Wine Startup Troubleshooting

    Existing Wine deployment only. These plain Compose commands intentionally use the compatibility docker-compose.yml path.

    Older Wine images may log missing Vulkan or EGL libraries. Update the existing Wine image first:

    docker compose pull
docker compose down
docker compose up -d
    Failed to load libvulkan.so.1
Failed to load libEGL.so.1

    A final WindowsServer pakchunk0 mount line means the package mounted successfully; it is not proof of a hang. Wine wrapper processes may normally wait in pipe_read or anon_pipe_read.

    🐧 Native Runtime Diagnostics

    Do not rely on container uptime or the final stdout line alone. Verify A2S readiness on UDP 27015 and inspect the Native container:

    docker compose -f docker-compose.native.yml ps
docker stats --no-stream
docker inspect conan-exiles-enhanced-native \
  --format 'status={{.State.Status}} oom={{.State.OOMKilled}} restart={{.RestartCount}}'
docker events --since 30m \
  --filter container=conan-exiles-enhanced-native
docker top conan-exiles-enhanced-native \
  -eo pid,ppid,stat,pcpu,pmem,wchan:32,comm
    free -h
grep -E 'CommitLimit|Committed_AS' /proc/meminfo
sysctl vm.overcommit_memory

    RAM Increased but Docker Still Shows the Old Limit

    After resizing a VM or container, restart Docker and verify that Docker and the host report the same total memory:

    sudo systemctl restart docker
docker info --format '{{.MemTotal}}'
free -b

    Native Exit Code 137

    Exit code 137 means SIGKILL; it does not prove OOM. Confirm memory exhaustion with OOMKilled=true or a Docker oom event.
    docker inspect conan-exiles-enhanced-native \
  --format 'exit={{.State.ExitCode}} oom={{.State.OOMKilled}}'
docker events --since 30m \
  --filter container=conan-exiles-enhanced-native

    🐧 Native Backup and Restore

    Native backups use SQLite snapshots and never mix a snapshot with separately copied live WAL/SHM files. Password values in archived INIs are replaced with [REDACTED].

    # Create and verify a portable Native world backup
./scripts/conan-backup.sh --runtime native create
./scripts/conan-backup.sh list --verify

# Restore is a non-mutating dry-run unless --apply is added
./scripts/conan-backup.sh --runtime native restore .conan-backups/ARCHIVE.tar.gz
./scripts/conan-backup.sh --runtime native restore .conan-backups/ARCHIVE.tar.gz --apply
    The unified tool discovers the labelled Native service and exact named volume, creates a pre-restore backup before replacement, and preserves prior running state. See the Operations guide for recovery after interruption.

    🔄 Wine-to-Native Runtime Migration

    Do not point Native at Wine volumes, and do not stop Wine manually first. Run plan while Wine is running. The apply command owns the stop, proves the source unused, creates new Native volumes, and keeps the original Wine data unchanged for rollback.
    ./scripts/migrate-compose-wine-to-native.sh plan
# Review the dry-run, then let the wrapper own the cutover
./scripts/migrate-compose-wine-to-native.sh apply

    🍷 Existing Wine Backup

    Existing Wine deployment only. Use the unified verified backup path instead of guessing Docker volume names.
    ./scripts/conan-backup.sh --runtime wine create
./scripts/conan-backup.sh list --verify

    🍷 Existing Wine Restore

    Existing Wine deployment only. Restore is a dry-run by default. Review the plan and verified pre-restore backup before adding --apply.
    ./scripts/conan-backup.sh --runtime wine restore .conan-backups/ARCHIVE.tar.gz
./scripts/conan-backup.sh --runtime wine restore .conan-backups/ARCHIVE.tar.gz --apply

    ⚠️ Enhanced Setting Status / Legacy Compatibility Notes

    The official Conan Exiles Enhanced server settings reference is the first source to check, but it is non-exhaustive. Absence from that list does not prove a setting is broken; it means the key still needs runtime verification on Enhanced before this project describes it as reliable.

    Officially documented in Enhanced

    Setting Status Details
    CraftingCostMultiplier ✅ Official Enhanced key Official Enhanced docs list this key, default 1.0f, Requires Restart: No. Runtime gameplay testing is still welcome.
    PlayerStaminaRegenSpeedScale ✅ Official Enhanced key Official Enhanced docs list this key, Requires Restart: No. Keep Admin Panel/database caveats in mind if a running world appears to ignore changes.

    Prefer Enhanced key / legacy alias uncertain

    Setting Status Details
    StaminaCostMultiplier ✅ Preferred Enhanced key Preferred/current key in the official Enhanced docs for stamina cost per action.
    PlayerStaminaCostMultiplier ⚠️ Legacy alias uncertain Older hosting docs mention it, but Enhanced docs prefer StaminaCostMultiplier. Do not prefer this unless runtime testing confirms a specific need.
    PlayerStaminaCostSprintMultiplier ⚠️ Legacy key Not found in the official Enhanced settings reference; needs Enhanced runtime verification.

    Not found in official Enhanced docs / runtime test needed

    Setting Status Details
    PlayerEncumbranceMultiplier ⚠️ Needs runtime test Legacy reports say it had no effect. Not found in the official Enhanced settings reference; needs runtime testing on Enhanced.
    PlayerSprintSpeedScale ⚠️ Needs runtime test Present in older references and hosting docs, but not found in the official Enhanced settings reference.
    PlayerMovementSpeedScale ⚠️ Needs runtime test Historically inconsistent and not found in the official Enhanced settings reference. Enhanced docs list PlayerMovementAccelerationMultiplier (BP) instead.
    PlayerHealthRegenSpeedScale ⚠️ Needs runtime test Present in older/hosting references, but not found in the official Enhanced settings reference; may require Admin Panel or database-aware testing.
    💡 Workaround: For unreliable settings, log into your server as Admin (ESC → Settings → Server Settings → Make Me Admin), then change the values from the in-game Admin Panel. Settings changed in-game are saved to the game database and take priority over the .ini file.
    ⚠️ Important: This Docker image rewrites ServerSettings.ini on every restart from your .env file. If you change settings via Admin Panel, they are stored in the game database and may take priority — but the .ini file will still show your .env values. If a legacy setting appears to do nothing, remove it from your .env to avoid confusion.

    About This Project

    This is a community Docker wrapper for hosting a Conan Exiles Enhanced dedicated server. It is built for people who want a practical Docker Compose setup with automatic game downloads, environment-based configuration, Steam Workshop mod support, and a web-based .env generator.
